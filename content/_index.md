This handbook explains *why* designs work, not only *what* they are called. Every article follows the same structure: the problem, the core idea, a diagram, a practical example, trade-offs, common mistakes and interview questions with answers.

- **Runnable code.** Java examples target **Java 21 LTS** and Spring examples target **Spring Boot 4.1**. The code on each page is included from source files that CI compiles, runs and checks on every build.
- **Diagrams you can edit.** Diagrams are written in Mermaid inside the articles, so they live in version control next to the text they explain.
- **Honest trade-offs.** No pattern or architecture style is presented as universally best. Each article says when *not* to use what it describes.

The handbook grows in batches. Section pages list the topics that are planned but not written yet, so you can always see what is complete.
