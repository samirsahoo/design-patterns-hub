System design means turning ambiguous requirements into an architecture that you can explain and defend. This section teaches one repeatable framework of 18 steps, from functional requirements to interview follow-ups. It then applies the framework to case studies.

- [Introduction to System Design](/system-design/introduction) presents the framework, including how to estimate capacity and how to label assumptions.
- [Diagram Building Blocks](/system-design/diagram-patterns) is a library of reusable Mermaid snippets for load balancers, caches, brokers, replication, sharding and other components.
- [Building blocks](/system-design/building-blocks) explains the reusable components: scaling steps, load balancing, caching, consistent hashing, CAP and PACELC, database choice, ID generation, queues and delivery semantics, real-time communication, deployment strategies, security fundamentals, DNS and probabilistic data structures.
- [Case studies](/system-design/case-studies) apply the framework end to end, each with an interactive architecture diagram: order management, URL shortener, rate limiter, payment system, proximity service, chat, news feed, notifications, video streaming, web crawler, search autocomplete, distributed key-value store, collaborative editing, stock exchange, ride sharing, metrics and alerting, flash sale, and file storage and sync.

For the theory behind replication, partitioning, transactions and consensus, see [Data-Intensive Systems](/data-systems).
