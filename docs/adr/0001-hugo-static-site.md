# ADR 0001: Hugo static site on GitHub Pages, no Node.js toolchain

Status: Accepted (2026-10-17)

## Context

The handbook must be maintainable by one person for years, be hosted for free on
GitHub Pages, need no database, backend, Docker or paid API, and must not require a
Node.js runtime to publish. Content must stay in Markdown, separate from layout code.

## Decision

- Use **Hugo** (pinned to v0.167.0, the extended edition) with templates written
  for this site — no third-party theme, so no theme upgrades can break the build.
- Use Hugo's template system introduced in v0.146 (`layouts/baseof.html`,
  `layouts/_partials/`, `layouts/_shortcodes/`, `layouts/_markup/`).
- Search is a static JSON index generated by Hugo (`/search-index.json`) and queried
  by a small vanilla JavaScript function (`assets/js/main.js`). No search library.
- Raw HTML in Markdown is disabled; callouts use the GitHub alert syntax
  (`> [!KEY]`), rendered by a blockquote render hook.
- Internal links are resolved by a link render hook that fails the build if the
  target page does not exist, and that works under any base path.

## Consequences

+ One static binary builds the site in well under a second.
+ The same build works at `/` and at a GitHub Pages project path (`/<repo>/`).
+ Broken internal links, prerequisites, related pages and learning-path steps fail
  the build instead of reaching readers.
- Custom templates must be maintained here; Hugo deprecations must be watched when
  upgrading (`hugo` prints them as warnings).
- Search is substring- and token-based, not a full-text engine. Revisit if the site
  grows past a few thousand pages or search quality becomes a problem.
